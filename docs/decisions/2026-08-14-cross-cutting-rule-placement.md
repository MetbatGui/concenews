# ADR: 교차 관심 프로세스 규칙의 지침 파일 배치

**Status**: Accepted
**Date**: 2026-08-14
**Slice**: Cross-cutting

## Context

ADR 강제(설계 결정 순서)와 TDD 강제(코드 작성 순서)가 `concenews-backend/AGENTS.md` 에만 기술되어 있었다.

지침 파일은 작업 디렉터리에 따라 선택적으로 로드된다. 백엔드 파일은 백엔드 작업 시에만 컨텍스트에 들어오므로, 루트 `docs/` 작업이나 향후 프론트엔드 작업에서는 두 규칙이 보이지 않는다.

두 규칙의 적용 범위는 실제로는 백엔드에 한정되지 않는다.

- ADR 트리거 6종([adr-process.md](../adr-process.md)) 중 "아키텍처 원칙 변경", "프로세스 규칙" 은 백엔드 코드와 무관하게 발동한다. ADR 산출물 위치(`docs/decisions/`)와 프로세스 문서도 루트 소관이다.
- TDD 는 프론트엔드를 포함한 모든 프로덕션 코드에 적용될 규칙이다.

실제로 본 리포에서 루트 `docs/workflow.md` 를 변경할 때 프로세스 규칙 트리거가 발동했으나, 이는 해당 세션이 우연히 백엔드 파일을 먼저 읽었기 때문에 인지된 것이었다. 규칙의 가시성이 작업 디렉터리에 의존하는 상태다.

## Options Considered

| 옵션 | Pros | Cons |
|------|------|------|
| A. 현행 유지 (백엔드에만) | 변경 없음 | 루트·프론트 작업에서 규칙 비가시. 적용 범위와 배치 불일치 |
| B. 양쪽에 중복 기술 | 어느 디렉터리에서도 보임 | SSOT 이중화. drift 발생 후 한쪽이 다른 쪽을 덮는 실패 경로 |
| C. 루트로 이전, 백엔드엔 백엔드 전용만 | 적용 범위와 배치 일치. 중복 없음 | 루트 지침 파일 분량 증가 |

## Decision

**옵션 C 채택.**

- ADR 강제와 TDD 강제를 루트 `AGENTS.md` 로 이전한다.
- `concenews-backend/AGENTS.md` 에는 백엔드 전용 규칙만 남긴다: `just check-branch-green` 검증, Modular Monolith·Docstring 사전 확인, Self-review 체크리스트.
- 배치 기준: **다른 계층·언어에도 적용될 규칙은 루트, 해당 계층의 도구·구조에 종속된 규칙은 하위 디렉터리.**

TDD 강제의 위반 판정 문구는 백엔드 경로(`src/`, `tests/`)를 예시로 유지하되, 규칙 자체는 계층 중립으로 기술한다.

## Rationale

규칙의 **적용 범위**와 **로드 범위**가 어긋나면, 규칙 준수 여부가 작업 디렉터리라는 무관한 변수에 좌우된다. 이는 준수율을 낮출 뿐 아니라 실패가 조용히 일어난다 — 규칙이 보이지 않았다는 사실 자체가 기록되지 않는다.

옵션 B(중복)는 [지식 저장 정책](../../AGENTS.md)의 SSOT 단일화 원칙에 정면으로 반한다. 같은 내용이 두 파일에 있으면 SSOT 가 0개가 되고, 이후 에이전트가 불일치를 "정리"하며 한쪽을 덮어 규칙이 소실된다.

루트 분량 증가는 감수한다. 같은 날 라우팅 기반 축소로 루트 `AGENTS.md` 를 161줄에서 89줄로 줄였고, 이전분을 포함해도 이전보다 작다. 다만 이 두 규칙은 라우팅 대상이 아니다 — **"언제 다른 문서를 봐야 하는가"를 판단하기 위한 상위 규칙이므로 상시 로드되어야 한다.**

## Reconsider When

- 프론트엔드가 백엔드와 다른 테스트 전략을 채택해 TDD 강제 문구를 계층별로 분기해야 할 때
- 루트 `AGENTS.md` 가 다시 비대해져 상시 로드 비용이 문제가 될 때. 단 그 경우에도 이 두 규칙은 마지막에 검토한다
